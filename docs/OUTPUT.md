# PNG, BufferedImage and SVG output (Issue #11)

All output formats are produced by **one** drawing implementation:
`Java2DCanvas`. Only the `Graphics2D` backend differs.

```
original Draw.io JS ──► DrawioJavaCanvas ──► DrawioCanvasBridge ──► CanvasRecorder
                                                                       │ (one JS run)
                                                                       ▼
                                                               CanvasRecording (DrawioScene)
                                                     ┌─────────────────┼──────────────────┐
                                                     ▼                 ▼                  ▼
                                            BoundsGraphics2D   BufferedImage G2D   Batik SVGGraphics2D
                                            (painted bounds)   → image / PNG       → SVG document
                                                     └──── each via new Java2DCanvas(graphics) ────┘
```

## Package `com.aresstack.drawio.render`

| Type | Purpose |
|------|---------|
| `DrawioScene` | Hand-off from the graph pipeline (#9): `paint(DrawioCanvas)` plus optional logical bounds (`mxGraphView.getGraphBounds()`). Must be repaintable. |
| `CanvasRecorder` | Records every `DrawioCanvas` call (dynamic proxy, so methods added to the interface later are recorded automatically). Only immutable arguments are accepted; primitive arrays are copied. `close()` is not recorded. Command count is limited. |
| `CanvasRecording` | Immutable, thread-safe recorded scene; replays the exact commands. Pass it to every output call so JavaScript runs only once. |
| `OutputOptions` | Immutable options with builder: scale, fit width, padding, background, DPI, bounds mode, anti-aliasing, SVG text mode and limits. |
| `OutputGeometry` | Resulting size and the diagram-to-pixel transform. |
| `SceneRenderer` | Stateless, thread-safe: `record`, `layout`, `renderImage`, `renderPng`/`writePng`, `renderSvg`/`writeSvg`. |
| `BoundsMode` | `UNION` (default), `PAINTED`, `LOGICAL`. |
| `OutputLimitException` | Unchecked; `getLimit()` is `COMMANDS`, `DIMENSION`, `PIXELS` or `SVG_SIZE`. The #12 facade maps it to `LIMIT_EXCEEDED`. |

```java
CanvasRecorder recorder = new CanvasRecorder();
// hand recorder.canvas() to new DrawioCanvasBridge(...) and run the original JS once
CanvasRecording scene = recorder.toScene(graphBoundsOrNull);

SceneRenderer renderer = new SceneRenderer();
OutputOptions options = OutputOptions.builder()
        .scale(2)                // or .width(800) or .resolution(192)
        .padding(10)             // unscaled output pixels, like Draw.io "border"
        .background(Color.WHITE) // null (default) = transparent
        .build();

BufferedImage image = renderer.renderImage(scene, options);
byte[] png = renderer.renderPng(scene, options);
String svg = renderer.renderSvg(scene, options);
```

## Geometry

`device = offset + scale * diagram`, with
`offset = floor(padding - scale * sourceOrigin)` per axis. Flooring at the
output scale is what Draw.io's export does (`Graph.getSvg` at the pinned
commit, jgraph/drawio#4938): content moves by whole output pixels, so 1-px
strokes that are crisp in the scene (half-pixel centers) stay crisp instead of
smearing over two pixels, and a fractional origin clips less than one pixel.

- **Size:** `width = ceil(sourceWidth * scale) + 2 * padding` (same for
  height), at least 1 pixel. With `width(n)` the total width is exactly `n`
  and the scale is `(n - 2 * padding) / sourceWidth`.
- **Source bounds:** by default the union of the logical graph bounds and the
  *measured painted bounds*. The painted bounds come from replaying the
  recording into `BoundsGraphics2D`, which nothing rasterizes; it widens every
  stroke with its actual `BasicStroke` (width, joins, miter, caps, dashes),
  applies transforms and clips, and includes text and images drawn through
  `Graphics2D`. Strokes, arrowheads, shadows and labels outside the logical
  bounds are therefore not clipped. `LOGICAL` reproduces Draw.io's own export
  framing and clips paint outside the logical bounds; `PAINTED` uses the
  tightest box.
- **Stroke control:** raster output uses `STROKE_PURE` (geometrically exact,
  like browsers). Batik's own rasterizer normalizes strokes for
  `shape-rendering="auto"`; tests rasterize our SVG with `geometricPrecision`
  to compare geometry, and then raster and SVG agree pixel for pixel.
- **SVG** uses the identical transform: user units are output pixels,
  `width`/`height` are the pixel size and `viewBox="0 0 width height"`.
- **DPI:** `dpi(x)` only writes the PNG `pHYs` chunk. `resolution(x)` also
  sets `scale = x / 96`, because Draw.io units are CSS pixels.

## SVG document

- Generated by Batik `SVGGraphics2D` (`batik-svggen` 1.17, Java 8) into a JDK
  DOM; serialized with a secure JAXP identity transformer.
- No DOCTYPE, no external DTD, no generator comment, `version="1.1"`,
  `xmlns` and `xmlns:xlink` declared on the root.
- Raster images are embedded as `data:image/png;base64` URIs, encoded with
  the JDK PNG writer in memory (Batik's own encoder needs batik-codec and
  threw a NullPointerException without it). Clip paths and gradients are
  referenced by local `url(#id)` only.
- Gradients: Batik only converts the legacy `GradientPaint` and fills
  everything else black. `SvgGradients` (a Batik `ExtensionHandler`) turns
  the `LinearGradientPaint`/`RadialGradientPaint` used by `Java2DCanvas` into
  `<linearGradient>`/`<radialGradient>` with `userSpaceOnUse` stops,
  spread method, gradient transform and stop opacity.
- Text: default is `<text>` (selectable, like Draw.io's SVG export). Java
  logical font names (`SansSerif`, `Serif`, `Monospaced`, `Dialog`) are
  replaced with CSS generics, because browsers do not know them. The viewer's
  fonts decide the final look, and underline/strikethrough are not emitted
  in this mode. `svgTextAsShapes(true)` writes outlines via `TextLayout`
  instead: identical to the raster output on every viewer, decorations
  included. Fonts are never embedded or referenced externally.
- `KEY_RENDERING=QUALITY` is applied only to raster output, because Batik maps
  it to `color-interpolation="linearRGB"`, which would change browser colors.
- `maxSvgChars` aborts serialization once the document grows too large.

## Canvas settings from the caller

`OutputOptions.imageLimits(bytes, pixels)` and `textMetrics(...)` configure
the `Java2DCanvas` used for **every** pass (painted bounds, raster, SVG). The
facade passes the request's `ResourcePolicy` image limits and the session's
`TextMetrics`, so images allowed by the policy are not rejected at replay and
painted label wraps match what the pipeline measured. Callers that already
computed an `OutputGeometry` can pass it to `renderImage`/`renderPng`/
`renderSvg(recording, geometry, options)` to skip a second bounds pass.

## Limits

| Option | Default |
|--------|---------|
| `maxCommands` | 2,000,000 recorded canvas commands |
| `maxDimension` | 16,384 pixels per side |
| `maxPixels` | 67,108,864 (64 Mi) pixels |
| `maxSvgChars` | 67,108,864 characters |

Limits are checked before any image buffer is allocated.

## Concurrency and Java 8

`SceneRenderer` and `CanvasRecording` are safe to use from several threads.
OpenJDK 8's Pisces rendering engine was observed to produce different
anti-aliased pixels (and potentially stroke outlines) roughly once per few
hundred renders when several threads rasterize at once; Java 21 (Marlin) was
deterministic in the same test. On Java 8 the Java2D step (bounds pass,
raster painting and SVG generation) is therefore serialized with a global
lock; JavaScript execution and recording still run in parallel. Override with
`-Dcom.aresstack.drawio.serializeJava2D=true|false`.

## Tests

- `CanvasRecorderTest`: order, replay, limits, immutability, close handling.
- `SceneRendererTest`: stroke-aware painted bounds, transforms and clips,
  bounds modes, scale/padding/fit width/resolution, transparent and opaque
  backgrounds, all limits, PNG pixel round trip and `pHYs` DPI, SVG structure
  (`viewBox`, namespaces, no DOCTYPE, no external `href`/`url()`), raster vs
  SVG pixel parity, alpha in both formats, single recording reused for all
  formats, deterministic parallel renders.
- `GatewayOutputParityTest`: runs the **original** BPMN `gateway2` JavaScript
  once through GraalJS into a recorder, then checks BufferedImage, PNG and SVG
  against the pinned official Draw.io viewer reference, plus scaled raster vs
  SVG parity and painted bounds.

- `SceneRendererTest` also covers the #10 canvas features in both formats:
  gradients (real SVG gradient, raster and SVG agree within 8/255 per
  channel), shadow inside the bounds, outlined text with underline (same
  amount of ink; only glyph edge anti-aliasing differs), selectable text with
  CSS generic families and XML escaping, and embedded `data:` images.

## Known limits

- Shadow blur is not rendered by `Java2DCanvas` (see docs/CANVAS.md), so it
  is absent in both formats alike.
- `<text>` mode depends on viewer fonts; for exact visual parity use
  `svgTextAsShapes(true)`.
